# 家で入る名湯（温泉地×入浴剤コーナー）設計書

2026-10-31 / 日本温泉Web（japan-onsen-web）への追加コーナー

## 1. 何を作るか・なぜ作るか

日本温泉Webの中に、**温泉地の名前がついた入浴剤・湯の花を、温泉地ごとに整理して比べるコーナー**を作る。

- 目的：日本温泉Webに楽天アフィリエイトの物販収益を乗せる。メディアの信頼を落とさずに、上乗せの収益を作る（大きな柱ではない）
- なぜこのテーマか：温泉地名の入浴剤は多いが、「どれが本物に近いのか」を温泉地ごとに横断して整理したサイトは、調べた範囲（2026-10-31）では見当たらなかった
- なぜ別サイトにしないか：温泉地ページ164か所の集客・内部リンク・ビルド／デプロイをそのまま使える。別サイトはアクセス0から始まり、「入浴剤 おすすめ」は大手の比較サイトが押さえている

## 2. このコーナーだけの価値：3段階の分類

温泉地名がついた商品を、次の3つに分けて見せる。これがコーナーの核で、全ページで一貫させる。

| 区分 | 名前（表示用・仮） | 条件 | 例 |
|---|---|---|---|
| ① | 本物の温泉成分 | 温泉そのものから採った成分（湯の花・温泉水・温泉ガスの結晶など）を使っていると、製造元・成分表示で確認できる | 別府・明礬温泉「薬用 湯の花」 |
| ② | 温泉地公認の再現 | 温泉地（観光協会・自治体）の公認・共同開発だと、メーカー公式で確認できる | バスクリン「日本の名湯」（17か所公認とされる） |
| ③ | 名前と香り・色 | 温泉地名はテーマで、再現品ではない（商品説明に「温泉の湯を再現したものではありません」とあるなど） | 白元アース「いい湯旅立ち」 |

- どの区分か裏取りできない商品は載せない
- ①に入れるには「天然」の根拠が必要。草津の湯の花では2006年に「天然」と誤認させる表示に排除命令が出た経緯がある。量産品の多くは天然ではないとされるので、①は特に厳しく見る

## 3. ゴール・やらないこと・失敗とみなす状態

**ゴール**
- 温泉地ページから、入浴剤の楽天リンクが継続的にクリックされ、少額でも売上が立つ
- 「草津 入浴剤」「◯◯温泉 湯の花」のような温泉地名＋入浴剤の検索で見つけてもらえる

**やらないこと**
- 効き目の比較・ランキング・点数づけ
- 「◯◯に効く」「本物の温泉と同じ効果」といった効能の表現（入浴剤の多くは医薬部外品で、薬機法の対象）
- 口コミ・体験談の創作
- 価格の表示（日本温泉Webは価格なし方針。「最新の価格は楽天で」と書く）
- 商品のない温泉地に空の枠を出すこと

**失敗とみなす状態（動いていても失敗）**
- 区分の誤り、特に③や②を①として載せること
- 本文のあちこちに楽天リンクが入り、温泉メディアとしての信頼が落ちること
- 販売終了の商品へのリンクが残ること

## 4. ページ構成

### 4-1. コーナーのトップ `/nyuyokuzai/`
1. 導入：「温泉地名の入浴剤は3種類ある」を図で説明（Claudeが作るSVG）
2. 温泉地から探す：都道府県ごとの一覧。商品がある温泉地だけを出す
3. 好みから探す：にごり湯・美肌系・硫黄の香り・炭酸など。タグで絞り込む
4. 贈り物向け：詰め合わせセット（「日本の名湯」のアソートなど）

### 4-2. 温泉地ごとの比較ページ `/nyuyokuzai/<温泉地id>`
1. 本物の湯：その温泉地の泉質・特徴。既存の `onsen.js` / `onsen_enrich.js` のデータを使う
2. 商品の一覧：区分のバッジ（①②③）、商品画像、名前、メーカー、区分の根拠（誰の公認か・何の成分か）、成分の要点、楽天リンク
3. 本物に行くなら：温泉地ページと、その温泉地の宿へ戻すリンク
4. 出典：区分の根拠にしたメーカー公式・製造元のページ
5. FAQ：日本温泉Webの既存のFAQの型（`faq_section`）に合わせる

### 4-3. 既存の温泉地ページへの追加
- `onsenDetail.js` のFAQの前に「家で味わうなら」の枠を1つ足す
- 中身は、区分が一番上の商品1〜2点と、比較ページへのリンク
- 商品がない温泉地には出さない

### 4-4. 広告の表記
- 楽天リンクがあるページには、広告（アフィリエイト）を含むことを明記する（ステマ規制）。既存サイトには手本になる表記がない（2026-10-31確認）ので、新しく決める〔Claude判断〕
  - コーナーの各ページ：冒頭に「このページには広告（楽天アフィリエイト）を含みます」
  - 温泉地ページの「家で味わうなら」枠：見出しの横に「PR」
- 既存の宿ページの楽天トラベルリンク（527件）にも表記がない。サイト全体に表記を付ける作業も合わせて行う（8章）

## 5. データ

- 新しいファイル `src/data/bath_salts.js` に商品を1件ずつ持たせる
- 1件の項目（案）：`id` / `name` / `maker` / `onsen_ids`（対応する温泉地。複数可）/ `tier`（1・2・3）/ `tier_basis`（区分の根拠の説明）/ `ingredients_note`（成分の要点）/ `tags`（にごり・硫黄など）/ `jan`（JANコード。分かるもの）/ `rakuten_item_codes`（候補を複数。上から順に使う）/ `is_gift` / `sources`（出典URL）/ `checked_at`（裏取りした日）
- 書き方の流儀は `onsen_enrich.js` に合わせる。公式情報で裏取りできた事実だけを書き、出典を必ず残す
- 温泉地idは `onsen.js` の id（例：`o-gunma-1`）を使う。日本温泉Webにない温泉地の商品（例：湯の川）は、温泉地ページを足すまで載せない〔Claude判断〕
- 温泉地の中の地区の商品（例：明礬は別府温泉の一地区）は、親の温泉地（別府＝`o-oita-1`）のページに載せ、商品カードに地区名を出す〔Claude判断〕

## 6. 画像・リンク・販売終了の検知

- 商品画像は楽天の商品検索APIで取る。アフィリエイトリンクと一緒に載せる使い方で、規約は着手時に確認する
- 楽天アフィリエイトIDは、日本温泉のThreads運用で使っている既存のIDを使う
- 接続の確認（2026-10-31 済み）：エンドポイント `https://openapi.rakuten.co.jp/ichibams/api/IchibaItem/Search/20260701`。`applicationId` はクエリで、`accessKey` はヘッダーで渡し、`Origin: https://japan-onsen-web.pages.dev` を付ける（Referer だけだと403、旧版20220601だと400）。キーは `.env`（gitignore済み）の `RAKUTEN_APP_ID` / `RAKUTEN_ACCESS_KEY` / `RAKUTEN_AFFILIATE_ID`
- 画像とクレジット（2026-11-01 確認）：楽天のクレジット表示ページでは、APIを使うサイトはクレジット表示が必須で、配布のHTMLを改変せずに使う決まり（https://webservice.rakuten.co.jp/guide/credit）。フッターにテキスト版「Supported by Rakuten Developers」を入れた。商品画像の掲載条件は規約（https://webservice.rakuten.co.jp/guide/rule）にもクレジットのページにも個別の記載がない。APIが返す画像URLをそのまま表示し、保存・加工はしない〔Claude判断〕
- アプリは楽天市場APIに加えて楽天トラベルAPIのスコープも登録済み（宿リンクの改善に将来使う）
- リンクは特定の出品（itemCode）に張る。1店の掲載終了で商品が消えないよう、候補を複数持つ〔Claude判断〕
- ビルド時にAPIで `rakuten_item_codes` を上から順に引き、最初に買える出品の画像URLとアフィリエイトURLを使う。結果はキャッシュし、APIが落ちていてもビルドは止めない
- 候補がすべて見つからないときは、`jan` で検索して代わりの出品を探し、ログに出す（自動で差し替えはせず、データ更新は手で行う）。それでもなければ、その商品を表示から外す
- 規約で画像が使えなかった場合は、画像なしのテキストカード＋区分のバッジ（Claude作のSVG）にする。価格が出る公式のリンク作成ツールは使わない〔Claude判断〕
- 価格はAPIから取れるが、表示しない

## 7. 載せる範囲（第1弾）

- 対象シリーズ：バスクリン「日本の名湯」、白元アース「いい湯旅立ち」、各温泉地の天然湯の花（別府・明礬など）。ほかのシリーズは第2弾以降
- カバー範囲の見込みは、164か所のうち30〜50か所〔推測。商品と温泉地の対応を数えて確定する〕
- 「日本の名湯」の17か所が具体的にどこかは未確認。メーカー公式で確定させる

## 8. 決まっていないこと・CEOに必要なこと

- 楽天の商品検索APIを使うには、Rakuten Developers のアプリID（無料）が要る。登録はCEOが行う（アカウント作成はClaudeが行えないため）
- 公開前の区分の確認：公開前に「商品・区分・根拠の出典」の対応表をCEOに見せ、確認を受けてから公開する（2026-10-31 CEO決定）
- 既存の宿ページ527件の広告表記：このコーナーと合わせて、サイト全体（宿ページ・フッター）にも広告表記を付ける（2026-10-31 CEO決定）
